## Nouveautés

- **Appli de bureau sous Linux : le vocal est expliqué, et on peut continuer dans son navigateur.** Le navigateur intégré de Linux (WebKitGTK, tel que Debian et Ubuntu le livrent) est compilé **sans WebRTC** : `RTCPeerConnection` n'y existe pas, même avec le réglage activé (vérifié sur WebKitGTK 2.52 d'Ubuntu 24.04). Le salon vocal (et l'appel d'un message privé) disait seulement « Ton navigateur ne permet pas les appels vocaux… Essaie avec… l'appli de bureau », ce qui renvoyait vers l'appli qui ne le peut pas. Désormais, dans l'appli de bureau, le message dit la vraie raison (« son navigateur intégré (WebKitGTK sous Linux) est livré sans WebRTC ») et un bouton **« Ouvrir dans mon navigateur »** ouvre la page de l'instance dans le navigateur du système (Chrome, Firefox…), qui a WebRTC.
- **Le message des vrais navigateurs ne promet plus l'appli de bureau partout** : « … ou, sous Windows et macOS, avec l'appli de bureau ».
- Traduit en anglais et en persan (3 textes).

## Pour les développeurs

- **Appli de bureau** : commande `open_in_browser` (`media.rs`), réservée à la page de l'instance dans la fenêtre principale, comme `update_*` : l'adresse ouverte est lue côté appli (la page courante), jamais donnée par la page ; seuls `http` et `https`. Ajoutée au manifeste (`build.rs`), aux permissions (`open_in_browser.toml`) et à la capacité de l'origine (`remote::allow_origin`).
- **Client** : `voice::unsupported_message()` répond d'abord « appli de bureau » (présence de `__TAURI_INTERNALS__`), puis HTTP, puis navigateur ; `voice::open_in_browser()` ; composant `OpenInBrowser` dans le salon vocal et l'appel d'un MP.
- Tests : `e2e/specs/voice-unsupported.spec.ts` (F04-U4 : appli de bureau simulée sans WebRTC, ordre message, bouton, détails, appel de la commande, échec sans que le bouton bouge ; F04-U5 : navigateur seul, pas de bouton) et `calls.spec.ts` F04-C8 (carte d'appel entrant).
- **Carte d'appel entrant** (appli de bureau sans WebRTC) : « Rejoindre » reste grisé, une phrase visible dit pourquoi (« Pas de vocal dans l'appli de bureau : réponds depuis ton navigateur. ») et un petit bouton « Ouvrir dans mon navigateur » est à côté. L'erreur d'ouverture a sa ligne réservée : rien ne bouge quand elle arrive.
- `open_in_browser` : deux ouvertures espacées d'au moins 2 s (une page ne peut pas l'appeler en boucle) ; le processus lancé est attendu dans un fil (pas de zombie `xdg-open`).
- Application de bureau : version 0.25.0.

## À savoir

- **Sous Linux, l'appli de bureau ne fait pas encore de vocal elle-même** : le navigateur intégré n'a pas WebRTC, et aucun réglage ne le remet. Le bouton ouvre la page dans le navigateur du système, où il faut se reconnecter ; le micro n'y est permis qu'en HTTPS ou sur cet ordinateur (localhost), comme dans tout navigateur. Windows et macOS ne sont pas touchés (WebView2 et WKWebView ont WebRTC).
- Une vraie solution pour Linux (navigateur intégré avec WebRTC, ou client vocal natif) reste à décider.
